# yololab · YOLO 游戏遮罩层

把 `train/` 训出来的权重直接**盖在游戏画面上**：一个置顶、鼠标穿透的透明窗口，
贴在游戏客户区上面逐帧推理，地形画线、怪物画框。不用切网页、不用截图。

```
yololab\
  overlay.py       ← 主力：游戏遮罩层（Win32 分层窗口 + BitBlt 抓帧）
  overlay.bat        双击启动遮罩层
  scene.py         ← 按相机取景框把导出的地图重建成一张 1366×768 游戏画面
  app.py             可选：网页版验收页（看静态截图更清楚）
  static\index.html  网页版界面
  samples\           示例图
  models\            想固定用某个权重就放这里
  out\               重建图 / 对比图输出
```

## 遮罩层：怎么用

```bat
yololab\overlay.bat
```

它会自动找标题含「冒险岛 / maple」的窗口和最新的 `best.pt`，然后**点一下游戏窗口**，
标注就浮上来了。控制台会每 5 秒打一行 `fps / ms / 怪 / 地形 / conf`。

```bat
python yololab\overlay.py --conf 0.45 --imgsz 640 --fps 15   :: 常用调参
python yololab\overlay.py --list                             :: 先看有哪些窗口
python yololab\overlay.py --window 怀旧服                     :: 指定窗口关键词
```

### 画什么

| 类别 | 画法 | 为什么 |
|---|---|---|
| `ground` | 绿色横线 | 标注框是「站立线往下盖 32px」，所以**框的上边就是角色站立线** |
| `slope` | 紫色虚线 | 同上；倾斜方向从 bbox 里推不出来（框不保留端点顺序），所以贴在上沿画虚线 |
| `rope` / `ladder` | 琥珀/橙色竖线 + 两端小横杠 | 框是「绳中心 ±16px」，**水平中线就是绳子本体** |
| 怪物 | 方框 + 名称 · 置信度 | 有名字和 id 才好对照 |
| 顶部中央 | `12.0 fps · 60 ms · 怪 3 · 地形 16 · conf 0.35` | 状态条 |

### 热键（Ctrl+Alt 系）

| 键 | 作用 | 键 | 作用 |
|---|---|---|---|
| `H` | 显示 / 隐藏遮罩 | `O`/`F8` | 暂停 / 继续推理（O 被占用时自动用 F8） |
| `G` | 地形线开关 | `[` `]` | 置信度 ±0.05 |
| `K` | 标签开关 | `2` | 推理尺寸 640→960→1280 |
| `Q` | 退出 | | |

控制台也能敲命令：`q h g k o c 0.5 i 960 ?`

### 为什么抓帧不走 mss / PrintWindow

这块踩了三个坑，记下来免得以后重试：

1. **PrintWindow 抓不到**：对这个游戏返回 0、整幅全黑（D3D 渲染不响应 WM_PRINT）。
2. **mss 抓屏幕会把自己的遮罩拍进去**：遮罩就盖在游戏上，下一帧推理的输入里
   带着上一帧画上去的线，等于喂自己的输出。实测 `WDA_EXCLUDEFROMCAPTURE`
   对 GDI BitBlt 抓屏**无效**（排除前后画面完全一致）。
3. **最终方案：BitBlt 读游戏客户区 DC** —— 单帧 8.6ms、内容实时、且**完全不含
   遮罩和其他窗口**，自我污染问题从根上消失。

### 已知限制

- **全屏独占模式看不到遮罩**，请用窗口模式（客户端默认就是窗口）。
- 游戏被别的窗口盖住 / 不在前台时，遮罩自动收起（判断依据：游戏窗口中心点最上层
  是不是它自己），避免线浮在别人窗口上；`--always-on` 可关掉这个行为。
- 抓的是游戏客户区，所以就算游戏被别的窗口盖住也能读到内容 —— 但遮罩会盖在
  那些窗口上面，这就是为什么默认加了前台门控。
- 遮罩是鼠标穿透的，不影响点游戏；但别指望它能点中东西。

### 性能（20 核 CPU）

| imgsz | 单帧推理 | 实测整环 |
|---|---|---|
| 640 | ~31 ms | 15 fps 稳定 |
| 960 | ~56 ms | 11~12 fps |
| 1280 | ~100 ms | 6~8 fps |

整环 = 抓帧 8.6ms + 推理 + PIL 绘制 + 贴图。

## 从资源重建一张游戏画面（scene.py）

给一张游戏截图，想知道它对应哪张地图、以及「这张图本来就存在，能不能复现」时用：

```bat
python yololab\scene.py 106000000 --at=-625,705 ^
    --locator --shot 截图.jpg
```

- `--at X,Y`：取景框左上角的**世界坐标**（相机位置，不是玩家坐标）
- `--locator`：在整图预览上画红框，标出这张截图在地图的哪一块
- `--shot`：额外输出三格对比图（真实截图 / 重建 / 50% 叠加）

输出在 `yololab\out\`。

**怎么求 `--at`**：拿截图和 1:1 渲染的整图做 SIFT 配准就行（截图里的 UI 会干扰，
先把左侧小地图和底部状态栏 mask 掉）。当前这张截图的结果是 `(-625, 705)`，
167 个内点、缩放 1.0。

**和 `wztool map-export --region` 的区别**：region 是「整图缩略图的裁剪」
（0.53x），而且背景沿用「屏幕中心 = 画面中心」的近似，远景会整块错位。
scene.py 直接按 1:1 渲染，并把 back 的 `rx/ry` 视差按客户端公式接进相机：

```
shift = rx * (683 - 相机世界x) / 100 + 683
```

另外 `info/cloud=1` 的图，客户端会额外画一层云（`Map.nx` 里没有 cloud.img），
导出的背景铺不满时天空会露出**纯蓝底砖**（如 `Back_dryRock_back_0` 那种 256×256 纯色）。
scene.py 会把这块纯色底砖换成地图自带的横向云带（900×210）双向平铺，天空才像游戏里
那样是云。前景逐像素精确，云层是近似——这一层本来就只存在于客户端引擎里。

## 网页版（可选）

想看静态截图、逐条对比框和置信度时用：

```bat
yololab\run.bat          :: http://127.0.0.1:8770
```

支持拖拽 / `Ctrl+V` 粘贴 / 示例图，右侧列类别计数和明细，可热切换权重。
和 `wztool web` 完全独立。

## 权重从哪来

按顺序自动找，选最新的 `best.pt`：

1. `yololab\models\*.pt`
2. `models\*.pt`
3. `train\runs\<round>\weights\best.pt`（当前用的就是这个）
4. 在 git worktree 里跑时，还会回主仓库找一遍

`--model` 可强制指定。
